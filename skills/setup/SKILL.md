Set up basivo-review for the repository in the current directory. Arguments: `$ARGUMENTS`

## 1. Preflight

Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/preflight.mjs"` from the repository root. Stop with a plain explanation when
`forge` is null (not a git repository) or `cli` is `missing`. If the working tree has uncommitted changes
(`git status --porcelain` prints anything), ask the user to commit or stash first: the setup writes files and
reverts anything it should not have touched, which is only safe on a clean tree.

## 2. Show the plan first

Run the dry run and show its output to the user:

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/engine.mjs" setup --repo-dir . --dry-run [--ci github]
```

Pass `--ci github` when the arguments say so, or when the user wants reviews to run on the repo's own GitHub
Actions as well (ask once if unclear; terminal-only is fine). It lists what will be written, which docs are kept
because the team wrote them, and which generated docs are stale and will be refreshed. Ask the user to confirm
before going on.

## 3. Write the docs

Run in the background and wait (2–5 minutes; one model run with a cost cap):

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/engine.mjs" setup --repo-dir . [--ci github]
```

Show the user the files written, the files kept, anything reverted, and the notes. Then open
`.factory/knowledge/overview.md` and `.factory/review.md` and show the first 30 lines of each so the user can
judge the quality.

## 4. Deliver on a branch

Ask with AskUserQuestion: "Commit these on a branch and open a pull request?" Options: "Yes, open a pull request",
"Commit on a branch only", "Leave the files uncommitted".

- Pull request: `git checkout -b basivo-review/setup && git add .factory .github/workflows/review.yml 2>/dev/null; git add .factory && git commit -m "Project knowledge and review rules for basivo-review" && git push -u origin basivo-review/setup && gh pr create --fill --title "Project knowledge for the reviewer" --body "Generated by /basivo-review:setup. Docs the team wrote were not changed. Edit anything that is wrong; re-running setup refreshes only generated docs whose sources changed."`
- Branch only: the same without `gh pr create`.
- Uncommitted: stop; say the files are in place.

Never commit to the default branch directly.

## Rules

- Team docs (any `.factory/knowledge/*.md` without `generated: true`) are never changed. If the engine reports it
  reverted one, say so.
- Re-running setup later is safe: it rewrites only generated docs whose `sources` changed and adds docs for new
  areas.
- Never print a token.
